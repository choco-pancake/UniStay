# Deploy UniStay to InfinityFree

Target: `https://unistaysads.infinityfreeapp.com`.

1. In the InfinityFree control panel, create an empty MySQL database. Record its **database hostname**, prefixed database name, username, and password. The hostname is not `localhost`.
2. On the XAMPP computer, run `powershell -ExecutionPolicy Bypass -File tools/prepare-infinityfree.ps1` from the repository root. This creates `scratch/infinityfree-<timestamp>/htdocs/` and `unistay-import.sql`. The export includes the current local records and omits triggers because InfinityFree's free MySQL account cannot create them. It excludes local credentials. Do not use `database/schema_infinityfree.sql`; it is an older, incompatible schema.
3. Edit `htdocs/config/hosting.local.php` in the prepared folder and replace the InfinityFree database placeholders. The preparation script creates this file from the example. The HTTPS app URL is already set to the target domain. Keep this file outside Git.
4. For mail and Google sign in, run the preparation script with `-IncludeLocalCredentials` to copy the existing local settings into the prepared folder. It rewrites the OAuth callback to `https://unistaysads.infinityfreeapp.com/auth/google_oauth.php`; also add that URI to the Google Cloud OAuth client. SMTP must use port 587 with TLS. The prepared folder then contains secrets: keep it private and do not commit it or upload it anywhere except the hosting account.
5. Import `unistay-import.sql` into the new database using InfinityFree phpMyAdmin. The SQL file belongs only in phpMyAdmin; do not upload it to `htdocs`. Check that the imported database has 14 tables and the expected users and dorms.
6. Upload the **contents** of the prepared `htdocs` directory to `/unistaysads.infinityfreeapp.com/htdocs` using the InfinityFree file manager or FTPS. For a scripted upload, put FTP credentials in ignored `scratch/infinityfree-ftp.netrc` using `machine ftpupload.net login YOUR_USER password YOUR_PASSWORD`, then run `powershell -ExecutionPolicy Bypass -File tools/upload-infinityfree.ps1 -PreparedDirectory scratch/infinityfree-<timestamp> -RemoteHtdocs /unistaysads.infinityfreeapp.com/htdocs`. The script checks the remote folder and never deletes remote files. Keep `vendor/`, `tenant/uploads/`, and `uploads/` in place. Do not upload `node_modules/`, the SQL dump, or development folders.
7. Open the HTTPS site and test sign in, booking decisions, a new upload, authorized document viewing, password reset mail, and Google sign in. Test that a direct URL under `uploads/permits/` returns 403. Check the admin subscriber page for queued email and process it there; free hosting does not provide cron jobs or shell access.

The site is intended for browser visitors. InfinityFree's browser challenge can block external API clients and webhooks. If an import or upload fails, keep the local export and retry the failed step rather than creating a second schema.
